## 触る前に

- **面・線・カメラ・スクロールの受け方は 006-G の複製。**
  `../006-sketches/NOTES.md` の「スクロールの受け方（G）— 5回作り直した」を先に読む
- 曲線は **直線 → 円弧 → 直線**。曲がるのは円弧の中だけ。Catmull-Rom は禁止（ぶよぶよ）
- 円弧の向き（sweep）は y が下向き：**下→右 0 ／ 右→下 1 ／ 下→左 1 ／ 左→下 0**
- 線の長さは必ず `getTotalLength()`。直値を書かない

## 008 で決めたこと（今日）

**線に理由を付けた。**線は段の下ではなく**段の中を通る**。見出しと中身のあいだ。
どの停留所でも同じ高さに罫があって、それが一本に繋がっている
（＝「見出しの下の罫」が、たまたま隣の停留所まで続いている）。
- 下に置いた版では、段が高い「進め方」で線が画面のいちばん下まで押し出されて、
  進み具合の帯と 17px しか離れず、**横線が二本並んで見えた**
- `SEAT_GAP` は 65 → **40**（上下に2回効くため）。CSS 側の空きは **80px**（その2倍）
- 「進め方」だけ、線に乗るのは**注文（例の2つ）まで**。出てきた紙は線の下

**停留所の間隔 1800px。**面は 8300×1600。
- 1280px の窓で縮尺 1.19 倍 → 画面に入るのは面の 1040px ぶん
- 1040 より広いだけでは足りない。1300px で組んだら、進め方の左下を線が斜めに
  横切って下の道具に被った。1800 なら余る
- **「落ちる区間が前後どちらからも見えない幅が要る」と書いていたが、これは撤回。**
  見えないことが問題だった（下の「ジェットコースターにしない」）。
  いまは逆に、**曲がりはじめが段の内側に入るように置いてある**（x2850）
- 縮尺は**いちばん広い段だけ**で決まる（`measure`）。だから段ごとに幅を変えていい
  （1040 / 1040 / 1000 / 900 / 760）

**着いた時点で、もう形になっている。**「進め方」は `show(0)` で最初から開いてある。
押すまで空にしていたら、線の下が 385px ぶん白いままで壊れて見えた。
押すと変わるのは「どの例を見るか」と「空欄が埋まるか」。
（007 で同じことを決めている：**最初から出しておいて、何もしなくても情報はある**）

**値と出どころは同じ行。**別の行にすると埋まったぶん段が縦に伸びて（3項目で 72px）、
それを先に確保すると縮尺が 1.19 → 1.04 に落ちて**全段の字が小さくなった。**
空欄の罫の高さも、埋まった行の高さ（1.85em）に揃える。

**`--rule` という色は存在しなかった。**`:root` にあるのは `--line`。
var() が解けない宣言は無効になるので、**罫が一本も引かれていなかった**
（空欄の罫、サービスの区切り、紙の枠、ぜんぶ）。空欄だけ琥珀の破線
（**うちが見つけたのはこの空欄**という印なので、ほかの罫と同じ色にしない）。

**G の名残は消した。**段の体裁（引用・例・見つけたあと・会社）、`.add`／`.reveal`、
狭い画面で段を割る話、`ROOM_N5` という名前。効かないか、効いて邪魔になるだけだった
（`.n2 .cap2` の `margin-top:110px` が新しい一行を 110px 下げていた）。
ロゴの行き先は「最後の段」ではなく**名前で引く**（008 の最後はお問い合わせ）。

**下の欄に行き先を並べない。**placeholder は「聞く」だけ。何を聞けるかは
すぐ横の一覧そのものが言う（並べたら 396px 埋まって字が切れた。G の hint と同じ失敗）。
空のときは**どれも選ばない**（enter が現在地へ行くように見えていた）。
当たらない語でも**一覧は畳まない**（「ありません」と書く場所ではない）。
移りは `goTo`（G のもの）に任せる。`scrollTo({behavior:'smooth'})` はブラウザ任せの
速さになって、ロゴを押したときと揃わない。

## 狭い画面を見た（2026-09-04、430×860 / 390×844）

**3つ壊れていた。ぜんぶ直した。**

**線が見出しを貫いていた。**狭い画面だけ、見出しの下の空きを 80px → **14px に詰めてあった**
（理由は「狭い画面では線が段の横に来ない」）。**面は一枚なので、線は幅に関係なく段の中を通る。**
詰めたぶん線が中身の一行目に重なって、**見出しに打ち消し線が引かれているように見えた。**
80px は SEAT_GAP（40）の2倍。**幅で変えてはいけない数字だった。**

**進め方の段が、画面の下から 74px はみ出していた。**寄り先（marks）を測る `measure()` は
`show(0)`（紙を入れる）より**先に走っていた。**広い画面では `.n2` の `min-height:385px` が
空の紙のぶんを立てていたので出なかったが、**狭い画面はその min-height を 0 にしてある**ので、
空の高さで寄り先が決まっていた。進み具合の帯にも被っていた。
直し方：`show(0)` のあとで `measure(); draw();`。**幅に関係なく「入っている紙」で決まる。**
（385px という数字は、もう寄り先には効いていない。効くのは読み込み中の一瞬だけ）

**`#hint` が body に無いのに、JS が触っていた。**最初のひと振りで例外が出て、
**そのフレームの draw() が飛んでいた**（狭い画面に限らない。広い画面でも同じ）。
無ければ触らないようにした。CSS（`.hint`、記号の svg、`.narrow` / `.wide` の出し分け）は
**全部残っているが、効いていない。**

## ジェットコースターにしない（2026-09-04）

本人の言葉、そのまま。

> 悪くないけど、ジェットコースターにはしないでって言った。
> 絶対画面内から予測できるような変化にするか、変わったとしても驚かせすぎないもの

**「って言った」——二度目。**一度目は会話の中で言われて、**どこにも書いていなかった。**
だから同じ形をもう一度作った。ここに置く。

**何が「ジェットコースター」だったか。**サービス → 進め方 の落差 730px（60度）。
1280×800 の窓で、**画面の高さより多い 869px を縦に動いていた**（109%）。
しかも落ちる区間は前後どちらの停留所からも見えない場所に置いてあって、
**平らな罫を見ている人には、その先で落ちることを知る手立てが無かった。**
（見えないように置いたのは、こちらが意図してやったこと。上の「停留所の間隔」を参照）

**直したこと。落差 730 → 180、角度 60度 → 11.7度。**縦の移動は 869px → **199px（画面の25%）。**
狭い画面（430×860）では 144px（17%）。

**曲がりはじめを、画面の中に入れた。**サービスの段は x1880〜2920 で、窓もちょうどその幅。
曲がりはじめを **x2850**——**縁の 70px 内側**に置いたので、
**見出しの下の罫が、右端で下へ傾いて画面から出ていく**（約 11px 下がる）。
進め方の側も同じで、**罫は左端で上から降りてくる**。
**行き先が、いま見えている罫そのものに書いてある。**
ここを段の外（x2920 より右）へ出すと、また見えない落下に戻る。

**VERT（縦に動くぶん足す間）は残したが、効きは 0.37秒 → 0.09秒。**
どの移りもほぼ 1.0秒で、速い区間がもう無い。

**残っている問い。**「落ちる線」は 006-G から持ってきたもので、
**落差を 180 にした時点で、G の見どころはほぼ無くなっている。**
段の高さを変える意味（＝縦に散らして驚かせる。G の NOTES「配置で驚かせる」）は、
この注文とは正面からぶつかる。**完全に平らにする案は、まだ試していない。**

## ガタガタの正体（2026-09-04）

> 線まっすぐになったのに遷移がガタガタしてる。揃えるならそこもそろえて

**揃っていなかったものが3つ。ぜんぶ揃えた。**

**罫の高さが、停留所ごとに上下していた。**これが本体。
カメラは段ごとに「その段の外形の真ん中」を画面の真ん中に置いていたので、
段の高さが違うぶん、**面の上では一本の高さにある罫が、画面では跳ねていた。**
実測 **304 / 286 / 313 / 267 / 337**（70px の幅）。
横に動いているだけなのに罫が上下する——これが「ガタガタ」。
直し方：**段の真ん中ではなく、罫を基準に置く。**段は罫から上下にぶら下がる。
いま全停留所で **306**（狭い画面では 268）。**移りの縦移動は 0。**
（`align` / `ALIGN_MIX` という 20% だけ寄せる折衷が書いてあったが、
どの停留所にも `align` が書かれておらず**一度も効いていなかった。**まるごと外した。）

**会社概要だけ縮尺が 0.975 だった。**4つの移りのうち2つで縮尺が動いていて、
**そこだけ画面の流れる速さが違っていた**（1フレーム 61.5 / 72.7px、ほかは 67.1px）。
ROOM_CO を消して全段そろえた。いま4つとも **67.1px、縮尺は 1.192 のまま動かない。**
**詰まって見えるなら ROOM を下げて全部で引くこと。一段だけ引かない。**

**移りごとのスクロール量が違った**（`SPANS = [3,3,2,2,1]`）。落ちる区間だけ長く
取ってあった名残。**同じだけ指を動かしても、進む量が移りによって 1.5 倍違っていた**
（押したときは glide が時間で動くので出ない。指で送ったときだけ出る）。`[2,2,2,2,1]` に。

**罫の高さは、余りを上下半分ずつにしない**（2026-09-04）。

> こうするんだったら線もうちょっと上でいい、もしくはカメラがもう少し下

**段は罫からほとんど下へぶら下がる。**罫の上にあるのは段の名前だけで、
例外は進め方（そこだけ例の2つが罫の上に乗る）。半分ずつにすると、
**どの停留所も上が空いて、中身が下に沈んで見えた。**
`LINE_HIGH`（余りのうち罫の上に置く割合）＝ **0.20**。
1280×800 で罫は **306 → 246**、430×860 で **268 → 235**。
0 まで上げると罫が 206 まで来るが、**そこまで行くと下が空きすぎる**（試して戻した）。

**まだ揺れていた。段が上がっていた**（2026-09-04）。

> やっぱりちょっと揺れてる。線が安定してないとイメージとして安定してないように見えるから避けて。

**`RISE = 10` が残っていた。初めて着く段だけ、下から 10px（画面で 12px）上がって座る。**
**罫（琥珀の線）は SVG で、段の外にある。**だから**段だけが上がって、
線との空きが着地のあいだ 12px 変わっていた。**

コードには「段ごと動かせば、線もラベルも一緒に動く」と書いてあったが、
そこでの「線」は**段の中の罫（border-top）**を指していた。琥珀の線は一緒に動かない。
**`RISE = 0`。段を縦に動かさない。出るのは濃さだけ。動くものは無い。**
（`data-rise` で段ごとに戻せるが、**戻すな。**戻すと線が揺れる。）

測り直した：初回の通過も、出だし（intro）も、**線の縦ぶれは 0.00px。**
段の縦ぶれも 0.00px。動いているのは横だけ。

**罫はもう一段上げた。**`LINE_HIGH` 0.20 → **0.08**。
1280×800 で **246 → 222**、430×860 で **235 → 223**。

**罫の上は、どの段も「段の名前」だけ**（2026-09-04）。

> なぜかちょっと低いなと思ったけど、サービスに合わせてこうなってるのか。
> 情報は全部下に入れて、タイトルだけ上にして。サービスも一緒。その分線は上げていい

**罫の高さは全段で揃えてある**ので、**罫の上がいちばん高い段が、全段の罫の高さを決める。**
それが進め方だった——そこだけリード文と例の2つを罫の上に乗せていた
（「進め方だけ、線に乗るのは注文（例の2つ）まで」）。**そのぶん他の4段まで一緒に下がっていた。**

`SEATS` の `.n2` の `on` を `.n2 .egs` → `.n2 .k` に。**5段そろって、罫の上は名前だけ。**
80px の空き（SEAT_GAP の2倍）も、罫のすぐ下に来るもの＝`.n2 .cap2` へ移した
（紙は例の下に 24px で続く）。

罫は **222 → 137**（1280×800）、**223 → 121**（430×860）。
`LINE_HIGH` は 0.08 のまま——**上がったのは、罫の上に乗るものが減ったぶん。**
段の上端は全段そろって 65（狭い画面で 61）。

**気をつけること：段の名前が、固定の社名（`.title`、top:20px）に近づいた。**
いま 1280×800 で 32px。これ以上罫を上げるなら、社名との関係を先に見ること。

**罫の高さは、段の名前の上下を均等にして決まる**（2026-09-04。`LINE_HIGH` は消した）。

> もうちょっと下げて。一番上にある不動の概要と線との間、文字の上下を均等にして

罫の上にあるのは、どの段も名前だけ。その名前は、**いちばん上の動かないもの
（社名の帯 `.title`）と、罫との間**に居る。**その上下を同じにする。**

名前の下の空きは、作りから **SEAT_GAP（40）× 縮尺**で決まっている。だから上も同じにすればいい：

```
LINE_AT = 社名の帯の下端 + SEAT_GAP × 縮尺 + up
```

（`up` ＝ 罫から段の上端までの張り出し。下がはみ出すときだけ、収まるまで上げる。）
