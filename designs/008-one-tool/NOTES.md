## 触る前に

- **面・線・カメラ・スクロールの受け方は 006-G の複製。**
  `../006-sketches/NOTES.md` の「スクロールの受け方（G）— 5回作り直した」を先に読む
- 曲線は **直線 → 円弧 → 直線**。曲がるのは円弧の中だけ。Catmull-Rom は禁止（ぶよぶよ）
- 円弧の向き（sweep）は y が下向き：**下→右 0 ／ 右→下 1 ／ 下→左 1 ／ 左→下 0**
- 線の長さは必ず `getTotalLength()`。直値を書かない

## 008 で決めたこと（今日）

**線に理由を付けた。**線は段の下ではなく**段の中を通る**。見出しと中身のあいだ。
どの停留所でも同じ高さに罫があって、それが一本に繋がっている
（＝「見出しの下の罫」が、たまたま隣の停留所まで続いている）。
- 下に置いた版では、段が高い「進め方」で線が画面のいちばん下まで押し出されて、
  進み具合の帯と 17px しか離れず、**横線が二本並んで見えた**
- `SEAT_GAP` は 65 → **40**（上下に2回効くため）。CSS 側の空きは **80px**（その2倍）
- 「進め方」だけ、線に乗るのは**注文（例の2つ）まで**。出てきた紙は線の下

**停留所の間隔 1800px。**面は 8300×1600。
- 1280px の窓で縮尺 1.19 倍 → 画面に入るのは面の 1040px ぶん
- 1040 より広いだけでは足りない。**落ちる区間（595px）が前後どちらの停留所からも
  見えない**幅が要る（1300px で組んだら、進め方の左下を線が斜めに横切って
  下の道具に被った）。1800 なら前後に 82px ずつ余る
- 縮尺は**いちばん広い段だけ**で決まる（`measure`）。だから段ごとに幅を変えていい
  （1040 / 1040 / 1000 / 900 / 760）

**着いた時点で、もう形になっている。**「進め方」は `show(0)` で最初から開いてある。
押すまで空にしていたら、線の下が 385px ぶん白いままで壊れて見えた。
押すと変わるのは「どの例を見るか」と「空欄が埋まるか」。
（007 で同じことを決めている：**最初から出しておいて、何もしなくても情報はある**）

**値と出どころは同じ行。**別の行にすると埋まったぶん段が縦に伸びて（3項目で 72px）、
それを先に確保すると縮尺が 1.19 → 1.04 に落ちて**全段の字が小さくなった。**
空欄の罫の高さも、埋まった行の高さ（1.85em）に揃える。

**`--rule` という色は存在しなかった。**`:root` にあるのは `--line`。
var() が解けない宣言は無効になるので、**罫が一本も引かれていなかった**
（空欄の罫、サービスの区切り、紙の枠、ぜんぶ）。空欄だけ琥珀の破線
（**うちが見つけたのはこの空欄**という印なので、ほかの罫と同じ色にしない）。

**G の名残は消した。**段の体裁（引用・例・見つけたあと・会社）、`.add`／`.reveal`、
狭い画面で段を割る話、`ROOM_N5` という名前。効かないか、効いて邪魔になるだけだった
（`.n2 .cap2` の `margin-top:110px` が新しい一行を 110px 下げていた）。
ロゴの行き先は「最後の段」ではなく**名前で引く**（008 の最後はお問い合わせ）。

**下の欄に行き先を並べない。**placeholder は「聞く」だけ。何を聞けるかは
すぐ横の一覧そのものが言う（並べたら 396px 埋まって字が切れた。G の hint と同じ失敗）。
空のときは**どれも選ばない**（enter が現在地へ行くように見えていた）。
当たらない語でも**一覧は畳まない**（「ありません」と書く場所ではない）。
移りは `goTo`（G のもの）に任せる。`scrollTo({behavior:'smooth'})` はブラウザ任せの
速さになって、ロゴを押したときと揃わない。

## 狭い画面を見た（2026-09-04、430×860 / 390×844）

**3つ壊れていた。ぜんぶ直した。**

**線が見出しを貫いていた。**狭い画面だけ、見出しの下の空きを 80px → **14px に詰めてあった**
（理由は「狭い画面では線が段の横に来ない」）。**面は一枚なので、線は幅に関係なく段の中を通る。**
詰めたぶん線が中身の一行目に重なって、**見出しに打ち消し線が引かれているように見えた。**
80px は SEAT_GAP（40）の2倍。**幅で変えてはいけない数字だった。**

**進め方の段が、画面の下から 74px はみ出していた。**寄り先（marks）を測る `measure()` は
`show(0)`（紙を入れる）より**先に走っていた。**広い画面では `.n2` の `min-height:385px` が
空の紙のぶんを立てていたので出なかったが、**狭い画面はその min-height を 0 にしてある**ので、
空の高さで寄り先が決まっていた。進み具合の帯にも被っていた。
直し方：`show(0)` のあとで `measure(); draw();`。**幅に関係なく「入っている紙」で決まる。**
（385px という数字は、もう寄り先には効いていない。効くのは読み込み中の一瞬だけ）

**`#hint` が body に無いのに、JS が触っていた。**最初のひと振りで例外が出て、
**そのフレームの draw() が飛んでいた**（狭い画面に限らない。広い画面でも同じ）。
無ければ触らないようにした。CSS（`.hint`、記号の svg、`.narrow` / `.wide` の出し分け）は
**全部残っているが、効いていない。**
