# 009 カード

**ただし題材は、コアを決める前に作ったもの。**次の「この案のコア」を先に読む。

## この案のコア（2026-09-08・**仮**）

**この節が上に立つ。**下の節は時系列の記録で、決めごとの寄せ集め。
**迷ったらここへ戻る**（本人 2026-09-08：「コンセプトがないね今」「考える前に置くな」）。

### コアとは何か（008 から。言い換えない）

> それが会社のどういう部分を見せたいか、そのためにどういう発想を取ってるか、がコア。
> で、日進月歩とかはコアじゃない。（本人、2026-09-03）

**理念「経営の力で『遊ぶように働く世界』をデザインする」と技術邁進感は方針。コアではない**
（`../008-one-tool/NOTES.md`）。挑戦・安定のような態度の言葉も、この定義では方針の層にいる。

009 は「体験するって思想以外全部別物」で始まったので、
**発想（体験）だけ 005 から引き継いで、「部分」に名前が無いまま作っていた。**そこを埋めた。

### 決めたこと

| | |
| --- | --- |
| **部分** | **制約を選ぶことで結果を出す会社。**自由に作らない／下流をやらない／人が書かない |
| **発想** | **体験**（005 から引き継ぎ）。訪問者にも選ばせて、**取ったぶん何かを失わせる** |

一言なら **「縛ると、動ける。」**

**根拠は事業の三つの選択がぜんぶ「制約を選ぶ」で揃っていること。**
ローコード＝自由に書ける代わりに遅い、を捨てた。上流工程中心＝作らない。AI＝人が書かない。
**偶然ではなく事業構造なので、他社が同じことを言えない。**

### なぜここに決めたか（挙がった六つを順に当てた）

| 候補 | 落ちた／残った理由 |
| --- | --- |
| 挑戦 | **態度の層。**どの新設会社にも貼れる。008 が外した「日進月歩」と同じところにいる |
| 安定 | 事業とは合う（ローコードは安定を買う技術）が、**「お遊び 7 割」と正面衝突**。しかも積み上げでしか証明できないので、一年目の会社が掲げると空になる |
| 変遷についていく | **社長の痛みには一番届く。**が、追随した歴史が無いので**証明できない**（安定と同じ弱点）。「ついていく」は受け身で姿勢としても弱い |
| **制約の中の自由・不自由** | **採用。**事業構造そのもの。相手（社長層）の言語。**実績が一件も要らない唯一の候補** |
| 不快が快に変わる | **結果であって部分ではない。**制約を選んだ結果として軽くなる。単独だと「使いやすくします」に落ちる。不快の当事者は現場で、社長ではない |
| 遊び | 理念そのもの＝**方針に分類済み**（008）。006 で一度「デモと繋がらないので UI を遊ばせた」→ 位置合わせのパズルになって外れている |

### 理念とのつながり

**遊びはルールがあるから成立する。**ルールの無いゲームは遊べない。
**制約は遊びの条件**なので、理念「遊ぶように働く」は方針のまま、矛盾なくこのコアの上に乗る。
006 の失敗（理念とデモが繋がらず、UI のほうを遊ばせた）は、ここでは起きない。

### 制約とは何の制約か（**ここを読み違えた**）

こちらは最初、制約を**選べる数を減らすこと**と取った（「半年でやるなら」で選択肢を絞る、という形を出した）。**違う。**

> 縛るのは違うね。カードになってる時点で見やすくなってるはずで、
> 見やすければ量が多くても遊び気分でしばけるっていう…イメージ（本人 2026-09-08）

**この案の制約は、カードという型そのもの。**

- **生の文＝自由。**何でも書ける。だから手がつかない
- **カード＝不自由。**一枚に一つ、書式が決まっている。**だから動ける**

**縛るのは量ではなく形。**だから **§4「量は減らない」はそのまま生きる**
（こちらは一度「真逆になる」と書いた。撤回）。むしろ**量が多いままさばけることが快の正体**なので、
減らしたら快が消える。

**不自由の側も既に画面に出ている。**型に入れると元の文の含みは落ちる。
だから 009 はカードに**元の一行を並べて置いてある**——あれが「失ったもの」の表示になっている。

### これで何が残り、何が変わるか

| 残る | 変わる |
| --- | --- |
| **カードという形**（一枚に判断が一つ、だから押せる） | ③が**見るだけ → さばく**。前回捨てた三択が戻る |
| **量は減らない**（同じ量なのに怖くない） | 手数だけ減る（**塊で押せる**。下を参照） |
| 題材（散らばった課題・要望）。**入れ替えなくていい** | 三択の理由。「見直せるを伝える」→ **落差の実演** |
| 体験という発想／説明を削る／量で殴る | ②の役目。うんざりさせる → **予想を作る** |

**機構も題材も生きて、意味と手数が変わる。**008 → 009 のときのような全捨てにはならない。

### 型 ─ 感情の順（2026-09-08）

> あ〜あるなあ〜と思わせつつ、一瞬不快体験させて、
> 快体験に繋げて自分ごとにさせたい（本人）

**あるなあ → 一瞬の不快 → 快 → 自分ごと。**

**自分ごとが入口ではなく出口になった。**前は「何件たまっていますか」と聞いて自分ごとから始めていた。
そして**「あるなあ」と「自分ごと」は別物**——前者は「うちにもある」で**まだ他人事**、
後者は快を通ったあとにしか来ない。

| 段 | 役目 | 作り |
| --- | --- | --- |
| ① 種 | 自分ごとの種。**一つだけ聞く** | 「いま何件くらい溜まっていますか」。**あるなあは③の題で起きる**（下の節。生の文は読まれない）|
| ② 一瞬の不快 | **予想を作る** | 生の山で「要るものと要らないものに分けてください」→ **見た瞬間に無理だと分かる** |
| ③ 快 | 落差 | カードで同じことをする。**塊で押せる**ので終わる |
| ④ 自分ごと | 名前が付く | 通り終わったところに理念（§「理念は最後に出る」がそのまま効く） |

### ②は失敗させない。**無理だと分からせる**

003 で「生成を一度失敗させる」は却下されている（`../IDEAS.md`）。004-F も
「騙された感が不快にならないか」で採られていない。**不快の作り方には既に線がある。**

- **失敗させる** → 実際に時間を使わせる。嫌になって帰る
- **無理だと分からせる** → 手をつける前に諦めがつく。**一瞬で済み、何も失っていないので帰らない**

だから②では**実際に仕分けさせない。**生の山を見て「これは無理」と分かった時点で次へ行ける。
不快は「嫌な作業をさせられた」ではなく**「手がつかない、という感触」**。

**不快の出どころは現実であって、会社や AI の無能ではない。**ここは越えない。

### ③の肝は「塊で押せる」こと

402 枚を一枚ずつ押させたら賽の河原。**終わりが見えないと達成感は出ない。**

- **生の文** ── 一行ずつしか扱えない。402 行なら 402 回。無理
- **カード** ── 関係ごとに固まっているので**塊で扱える。402 件が 40 手ほどで終わる**

**量は減らないまま、手数だけ減る。**これが「見やすければ量が多くても遊び気分でしばける」の実体。

そしてコアと直結する：

> **型に入れた（不自由）→ 同じ形だから比べられる → 塊になる → 一手で片付く（自由）**

### 分担 ── 見抜くのは機械、決めるのは人

**塊を最初から固めて出すと、一番難しいところを機械が済ませてしまう。**
「権限の件が 17 個ある」と見抜くのが②で無理だと思った部分そのもので、
そこを機械が済ませると、人がやるのは**できあがった塊にハンコを押すこと**になる。
落差は出るが、**できるようになったのが自分ではなく機械に見える。**

三つの形を比べた（本人 2026-09-08：C で合意）。

| | 形 | 判断 |
| --- | --- | --- |
| A | 最初から固まっている（いまの 009） | 速いが、人がやるのはハンコ |
| B | 押した結果として固まる | 一手が効いた感は出るが、**なぜ 17 枚消えたか分からないと不気味** |
| **C** | **同じ件に同じ印が付いている。**一枚押すと「同じ印が 16 枚あります」でまとめて押せる | **採用** |

C の理由は二つ。

- **分担が画面に出る。**AI は「これ同じみたいですよ」まで、**決めるのは人。**
  §2「AI は下地と細かい推論をやる。カードに推論を載せない」と合う
- **この会社の仕事そのもの。**上流工程中心＝**決めることを人が持つ。**
  作業は機械に渡して、判断は渡さない。**デモの分担が、そのまま事業の分担になる**

A だと「AI が整理してくれるサービス」に見えて、上流工程の会社に見えない。

### 達成感は落差から。**数字は出さない**

達成感の出どころは三つに分けられる。

- **報酬**（点数・レベル・達成演出）── §5 で却下済み
- **進捗**（積まれる・減る）── 台帳の案。順繰りを捨てたときに一緒に消えた。戻す余地はある
- **落差**（思ったより楽だった）── **これを採る**

だから②の不快には「一瞬の嫌さ」以上の役目がある。**予想を作る段**であって、
それが無いと③に落差が生まれない。

**楽しさは達成感とは別で、テンポから出す。**カードが関係ごとに固まっているので
**同じ判断が続く**。最初の数枚は迷って、途中から連打になる。
速くなるのは演出ではなく実際に速くなるので、報酬にはならない。

**実測の数字は出さない**（本人 2026-09-08：「体感で」）。
「n 分で終わった」は却下ではないが（003 の実測秒数は生きている）、取らない。

**そのぶん逃げ道が消える。**数字は「楽になった」と言葉で言ってしまえる装置だったので、
無いと**本当に詰まって、本当に速く終わらないと何も残らない。**
設計の重心が、演出ではなく②と③の実装そのものに移る。

**落差は体で感じさせて、名前は理念が付ける。**

### 「得る」の中身

**モノではない。**§1 で一度却下されている。

> 持ち帰るとかじゃなくて、その体験から何を得てほしいかって知見の話（本人）

得るのは **「自分がさばけた」という事実**と、**それを可能にしたのは形だった**という気づき。
終わりに置くのは一行でいい（達成演出は却下リストにある）。

## 話し合いで決まったこと（2026-09-07）

順に潰していったので、順のまま残す。**却下の理由も残す**（同じ案を二度出さないため）。

### 1. 何を思わせたいか

> **「積み上がったやつ、見直せるんだ」**

痛みは**積み重ね**。最初は良かった。足していくうちに量になって、いまは誰も全体を見ていない。
**足すのは簡単で、見直すのが大変。**どの会社にもあるので、業種を選ばない。

**ここに至るまでに三回外している。**外した順に：

| 出した答え | なぜ違ったか |
| --- | --- |
| 「持ち帰るもの＝自社の見え方」 | **モノの話をした。**本人：「持ち帰るとかじゃなくて、その体験から何を得てほしいかって知見の話」 |
| 「理念と事業がつながった状態」 | 知見の話にはなったが、**感情ではなかった。**本人：「どういう感情になってほしいの？って話」 |
| 「羨ましい」→「欲しい」 | **感情に名前を付けにいった。**本人：「欲しいとかじゃなくて、結果そのデモを受けて何を思わせたい？何を見せたい？って話」 |
| 「読めないから人に任せるしかなかった」 | 惜しいが違う。読めないんじゃなく**積み上がって見直せない** |

### 2. 構造

**うじゃうじゃ → カード → 仕分け（ハンコ）→ 台帳**

- 重い側と軽い側で**中身も量も同じ**。変わるのは形だけ
- **量は減らない。**「それが読みやすくなるためのものだから」（本人）。
  減らすと「端折られた」が残る。山場は「少なくなった」ではなく**「同じ量なのに怖くない」**
- カードは**一枚に判断が一つ**。だから押せる
- 仕分けは三択：**これ要る／これ要らない／これはもうやった。**
  三択が成立するのは、全部が**過去に一度決めたもの**だから。新規なら「要らない」は出てこない
- **新規追加も同じカード・同じ押し方。**見直しと追加が同じ場所にあれば、次の積み重ねが起きない
- AI は**下地と細かい推論**をやる。**カードに推論を載せない**（載せたら PDF に戻る）

### 3. 面倒（重い側）

**面倒の正体は量。**中身の質ではない。

> 量で見せればいい（本人）

これで**中身が汎用でよくなる。**当たり障りのない文章でも、量があれば読めない。
題材選びで悩む必要が消えた。**読ませないので中身は何でもいい。**

- **恥をかかせない。**読めないのは自分のせいではない
- **書かせない。**手が止まって離脱するのは書かせたとき

**却下：**PDF をサイトに出す形（本人：「PDF いちいちサイトで出すのかって話」）。

### 4. 枚数

**多くていい。無限でもいい**（本人）。

無限は「終わらない」ので、そのまま出すと賽の河原になる。**軽い側でうんざりが出たら全部台無し。**
抜け道は**台帳**（本人が最初に挙げた言葉の中にあった）：

**減らないのは束。増えるのは自分が押した側。**押したカードが台帳に積まれる。
束は無限のままでいいが、台帳が厚くなるのは目に見える。**進んでいるのは山ではなく自分。**

### 5. ゲームにしない線引き

> ゲーム要素増やしすぎるとちょっと脱線するからなあ（本人）

**報酬を足すとゲームになる。手触りを足してもゲームにならない。**（本人：「その線引きは良いよ」）

- 足さない：点数、レベル、コンボ、達成演出、音
- 足す：重さ、慣性、めくれ、影、押したときのわずかなずれ、積まれた束の厚み

### 6. 理念の主語

**遊ぶように働くのは、アルターデザイン自身**（本人）。訪問者ではないし、客でもない。

そして**カード・ハンコ・仕分けは「会社の働き方」ではなく「会社が提供するコンテンツ」**
（本人：「それ会社のやり方じゃなくて、会社が提供するコンテンツの話」）。ここは混ぜない。

- **商品** ＝ うじゃうじゃをカードにして仕分けさせる仕組み
- **理念** ＝ 会社が遊ぶように働く。商品の説明ではない

### 7. 一言（「あそこのサイト、〜なんですよ」）は設計目標にしない

> その一言ってこっちが設定してやるものじゃなくない？結果どういうものなのかであって、
> 意図としておいたら意味ない（本人）

**結果として言えるかどうかは、作った後に人が決めること。**目標に置いた時点で標語作りになる。
`../IDEAS.md` の「一言にならない案は落ちる」も、この基準でいくと危うい。

### 8. 並び ─ 入口

> 軽い入口置いたら？で、会社案内自体の動線も軽く（本人）

**入口は、カードが置いてある一枚。**

- 真ん中に大きいカード一枚。社名と事業の一行。**それだけ読めば何の会社か分かる**
- 周りに押せるカード：サービス／会社概要／お問い合わせ／体験の口。**全部同じカード**
- 用がある人は一枚押せば着く（＝動線が軽い）
- 体験も同じ大きさで並んでいる。**隠さない**

**007 の失敗と区別がつく。**007 がダメだったのは普通の入口を置いたことではなく、
**体験を隠したこと**（サービス01の下に小さく「実物を見る」を一つ置いただけだった。`4314c31`）。
**軽い ≠ 隠す。**

理由：
1. サイト全体の言葉がカードなので、入口もカードでいい。別の言語で作るとそこで一度切れる
2. **押し方をここで覚える。**入口でカードを押した人は、体験に入ったとき説明が要らない
3. カードが数枚置いてあるだけの画面は、それ以上軽くならない

**枚数は決め打ちしない**（2026-09-07）。本人：「お知らせとかもあるはずだしね」。

最初は4列を決め打ちしていたので、5枚目を足すと 4＋1 の間抜けな折り返しになった。

**一度目の直しは外した。**余った列を残りで分け合う形（flex で引き伸ばす）にしたら、
6枚が 4＋2 になって、**題名しか無いカードが倍の幅になり空箱に見えた。**
本人：「こうなるとちょっと見栄え悪いな〜4超えるとね」。

**いまは段が揃うように列を割り直している。**一段に入る上限（広い画面で4）から
何段になるかを出して、その段数で割る。**全部同じ大きさで、どの段も端まで揃う。**

| 枚数 | 列 | 並び |
| --- | --- | --- |
| 4 | 4 | 203 ×4 |
| 5 | 3 | 276 ×3 ／ 276 ×2 |
| 6 | 3 | 276 ×3 ／ 276 ×3 |
| 7 | 4 | 203 ×4 ／ 203 ×3 |
| 10 | 4 | 203 ×4 ／ 203 ×4 ／ 203 ×2 |

最後の段が余るのは残す。**引き伸ばして埋めるより、大きさが揃っているほうがいい**
——これが分かったのが今回の収穫。狭い画面では上限が 2（720px 以下）／1（420px 以下）。

**上限は決めていない。**「何枚からメニューに見えるか」は実物を見ないと決められないので、
先に数字を置かない。**縦積み（狭い画面）は何枚あっても崩れない**——本人：
「スマホだと縦に並んでいい感じになりそうだけどなあ」。増えることには強い形。

**入口に置いていいのは分類。項目は中に入れる。**実績が10件あっても入口は1枚。
ここを崩すと、サイト自身が「積み上がって見直せない」を作る。

**「お知らせ」「実績」を枠だけ入れた**（本人：「いいよいれて」）。6枚で 4＋2 になる。
**どちらも公式サイトに無いので、中身は書いていない。**開くと「中身はまだ決めていません」
とだけ出る。**空の箱を作らない**——決まっていないことは、決まっていないと書く。

### 一覧はカード、中身はページ（2026-09-07）

  `pageshow` で開き直す。**これが無いと、一件読むたびにカードを開き直すことになって、
  同じ手間が別の場所に出る**

  頭の社名カードと同じ形なので、**戻り方に新しい部品を足していない**

**実績はまだカードのまま**（枠だけ）。中身が決まったら同じ形にする。

`html` に `scrollbar-gutter:stable`。カードを開くと `body` を止める（`overflow:hidden`）ので、

873px、**上は切れずスクロールで下端まで届く**。

## 体験（`try.html`）─ 粗い一枚（2026-09-07）

**字の大きさも間もまだ詰めていない。**変換の瞬間が効くかどうかを見るために作った。
本人：「まあそこは簡易的な体験だからな」——作り込まずに、通じる最小限で。

### 思わせたいことが動いた

最初は**「積み上がったやつ、見直せるんだ」**だった。本人の直し：

> 見直せるんだ〜というよりこの方がいいなと思わせる方かな

**発見（できるのか）ではなく、選好（こっちがいい）。**ここから二つ出た。

1. **比較が要る。**「この方が」には相手が要るので、**重い側は省略できない工程**になる
2. **重い側は「無理」ではなく「やってられない」。**無理なものを見せると、返ってくるのは
   「できるのか」＝発見のほう。**読めば分かる。ただ、やってられない**——そこで初めて
   「こっちのほうがいい」になる

**これで「ソースコード」が落ちた。**あれは「読めない」＝無理の側。0.5秒で伝わるのは強いが、
伝わるのが「無理」なので感情がずれる。並べたのは**業務のルール**（読めるけど多い）。

### カード化の値打ちは「関係が見えること」

こちらは最初「一件を探させる」と考えていた。本人の直し：

> こことここが被ってて、ここのためにここが必要で、後何が決まってなくて…みたいなのが
> できるってことなんじゃないんかな

**重い側の痛みは「探しにくい」ではない。**一行ずつは読める。読めるのに、
**40行目と380行目が矛盾していることが見えない。**全体の関係だけが見えない。

そして**三択が腑に落ちる場所がここ。関係が見えて初めて押せる。**
被っていると分かるから「要らない」が押せる。何かのために要ると分かるから「要る」が押せる。
うじゃうじゃの中で三択を出されても押せないのは、決断力ではなく**判断の材料が無いから。**

出どころは本人が最初に書いた四段：業務記述・**不足確認**・候補選択・**整合性確認**。

### 重い側では決めさせない

> 決めるところまでさせなくていいんじゃない？（本人）

重い側で決めさせると、「重いやり方でも決められる」ことを見せてしまう。
**探すだけで止めれば、決めやすさが軽い側だけのものになって差がはっきりする。**
本人の言葉でいえば、うじゃうじゃの中では「これは何をしているのか」を先に読まないと
いけない。**カードはその前段が済んでいる。**重い側にやらせるのは前段だけ。

### 作りで効かせたところ

- **同じ行がそのままカードになる。**別のものに差し替えていない。詰まっていたものが開くだけ。
  **だから「量は同じ」が嘘にならない**（`.stack li` の見た目が変わるだけ）
- **背景が動く。**重い側がいちばん暗い（`#171b22`）→ カードになると明るい（`#e8ebee`）。
  入口がいちばん明るい。**「背景色から組み立てなおす」がここで効く**
- **増えるのは台帳の側。**押した一件は選んだ山へ飛んでいく。
  （※ここは後で作り直した。下の「『減らない』を売りにしない」と「順繰り」を参照）
- **理念は最後に出る。**通り終わってから名前が付く。先に出すと標語に戻る

### 題材を課題管理表に替えた（2026-09-07）

### 題を外した——**表にしてある時点で整理済みだった**（2026-09-07）

> というか、件名になってて同じファイル内にある時点でかなり整理されてると思うよって言ってる（本人）

前の節でシートの形を崩したが、**それでも足りなかった。**
一つ前の直しは「表そのものを荒らす」ところまでで、
**題（件名）が付いていて、一つのファイルに集まっている**——
そこがまだ**整理の結果**だった。誰かが読んで、要点を書き出して、一箇所に集めた状態。

いま出しているのは、**題の無い生の文**で、出どころも散っている：

| 出どころ | 何が書いてあるか |
| --- | --- |
| `mail` | 「先日の帳票、桁がずれているとのことでした。原因はまだ分かっていません。」 |

- **参照の番号すら出さなくなった。**前は「→ 19 31 ??」と番号を出していたが、
  それは**もう誰かが関係に気づいた印**。生の材料にそんな桁は無い
- **桁を持つのは六つのうち一つ**（Excel の塊）。
  本人の言うとおり、**表になっているものは、まだ良いほう**——
  その「良いほう」がこれしかない、という絵になった
- しめの数字も**「無いもの」を数える**形に替えた：
  `402 fragments · 67 sources · 題が付いていない 336 · 状態がどこにも無い 325`。
  荒れの量は、値の揺れではなく**書かれていないことの量**だった

**カードになって初めて出るもの**（＝この仕組みの出力）：

1. **題。**生の一行には無い。「先日の帳票、桁がずれている…」→ **帳票の桁がずれる**
2. **出どころ。**どのメールの、どの議事録の、何ページの一行だったか
3. **関係。**被っている／何かのために要る／まだ決まっていない
4. **元の一行。**題と並べて置く——**すり替えていないことが、ここで見える**
5. 状態・担当・期限。**三つとも無いときは一行にまとめる**

これで、可視化の中身が**並べ替えではなく変換**になった。
前は「同じ表を綺麗に並べ直した」だったので、
「で、カードにして何が変わったの？」に答えが無かった。

- 帯の中の並びは**読む順**にした：題と出どころ → 関係 → 元の一行 → 欄。
  組んである順（生の文が先。表の段がそれを使う）とは違うので、
  写したあとで二つの節点を後ろへ動かしている（**作り直していない**）
- 件数の選択肢を **36／120／402** に替えた（出どころ 6 つ × 6 行が一周）。
  402 なら「400 件以上」が嘘にならない
- 捨てたもの：シートごとの形違い（全角番号・和暦・一行詰め込み・メモ桁）。
  **形の違いより、題が無いことのほうが効く**

### カードの中身を、機械が書いた一行にした（2026-09-08）

| 生の文（②の山と帯に出る） | カードに出る一行 |
| --- | --- |
| 帳票は最大 99 行。ただし旧帳票は 50 行のまま。 | **行数の上限が二つある（新 99 行／旧 50 行）** |
| あの帳票、また数字が一列ずれてました | **数字が一列ずれる、と現場から再報告** |
| 帳票の桁ずれ（再） | **桁ずれが、また別に登録されている** |
| ・帳票の桁の件、報告あり。原因調査中。 | **桁の件は「調査中」のまま止まっている** |

同じ件が何度も立っていることが、一覧の上で分かる。

### まとめが「件」で止まっていた ── 断片 → 言い方 → 件（2026-09-08）

```

言い方  60 通り     ← ③のカード。同じ言い方は一枚にまとまって「n か所」
```

#### 効いたのは見た目だけではない

| | 前 | いま |
| --- | --- | --- |
| カード | 120 枚（402 なら 402 枚） | **60 枚（何件でも 60）** |
| 縦 | 9,840px | **5,533px** |
| 402 のとき | もっと長い | **同じ 5,533px** |

**402 と答えても縦が伸びない。**枚数は数字として残る（「402 枚は、12 件でした」
