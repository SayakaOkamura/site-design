## 判断の指針

1. **変さには理由が要る。**理由のある変は主張になり、理由のない変はふざけになる。
   F が外れたのはここ（理由が自嘲）
2. **開いた瞬間に、これが何で、何をすればいいかを言う。**主張はそのあと。
   パッと見て分からないものは、雑談では二度と開かれない
3. **会社らしさ＝取引相手として信用できること。**面白さとは別の軸。
   責任の所在が見える・続く感じがある・他人に説明できる・**読める**。
   読みにくいものは、面白くても信用を落とす
4. **動きは飾りであって、中身を出す条件にしない。**素の状態を「見える」にして、
   `prefers-reduced-motion` では動きを切る。動かない環境で中身が消えてはいけない
5. **気づいた時点で直す。**指摘されてからではなく。261本の件（下記）で踏んだ

## 運用メモ

### スクロールの受け方（G）— 5回作り直した。触る前にここを読むこと

**結論：自前で受けるのをやめた。**本物の横スクロール容器（`#view`）に
`scroll-snap-type: x mandatory` を敷いて、慣性の計算はブラウザに任せる。
こちらは `scrollLeft` を読んで、いま何段目かを出すだけ。

なぜ自前をやめたか。**wheel イベントには「指が触れた／離れた」を表す標準の情報が無い。**
Chrome は慣性かどうかも教えてくれない。だから自前で受ける限り、
delta の大きさと時間の間隔から「ひと振りがどこで終わったか」を**推測する**しかない。
4回作って4回とも、別の壊れ方をした。

| やったこと | 何が起きたか |
| --- | --- |
| イベント1回＝1段 | ひと振りで最後まで飛ぶ |
| 静止するまで次を受け付けない | 回し続けると解除タイマーが毎回リセットされ、二度と進まない。ゆっくり回すと閾値に届く前に溜めが捨てられ、いつまでも進まない |
| 静止待ちをやめて時間で切る | スクロールが続く限り 0.62 秒ごとに一段進む。止まるバグを直して、暴走するバグを作った |
| 時間ベースの保険（`WAIT`）を足す | 慣性の途中で解除が効いて、手を止めたあとに一段進む |
| 絶対値の下限（`FLOOR`）で振りの終わりを見る | 「慣性の尻尾だから小さい」と「そっと振ったから小さい」が区別できない |
| 合図を「間があいたこと」だけにする | **前提が間違っていた**（下記） |
| 「減りきったあとに大きくなったら触り直し」で見る | それでも飛んだ。ここで自前をやめた |

**間違っていた前提。**「慣性は途切れずに来るので、間があくことは絶対にない」と書いたが、
そうではない。**慣性が走っているうちに振り直すと、新しい振りが同じ流れに混ざって間があかない。**
だから二振り目が受け付けられず進まない。そのまま何度か振ると、慣性が終わった瞬間に
まとめて解除されて飛ぶ。**「進まない」と「飛ぶ」は別のバグではなく、同じ原因の表と裏だった。**

**いまの作り。**

```
#stage   見る層。position:fixed。pointer-events:none で触らせない
         （例外：問い合わせのリンクだけ pointer-events:auto）
#view    触る層。overflow-x:auto + scroll-snap-type:x mandatory
#track   停留所を段の数だけ横に並べる（1つ＝画面いっぱいの幅、中身は空）
```

- `scroll` を受けて `scrollLeft / 画面幅` を出す。**これがそのまま「何段目か」で、
  段と段のあいだは小数になる。**寄り先（中心と縮尺）を混ぜて出すので、
  段で切り替わるのではなく1枚の上を滑って見える
- 寄り先は `measure()` で先に全部測っておく。毎回測ると、測っている先が動いてがくつく
- `#canvas` と進み具合の `transition` は**外した。**スクロールに毎フレーム追従するので、
  transition があると遅れてついてくる
- 縦に回したぶんを横に流すのは**ブラウザがやる**（横にしかスクロールしない容器なので）。
  自前の wheel ハンドラは置かない。**置くと `scrollLeft` の代入が mandatory snap と
  ぶつかって、1イベントごとに吸い寄せられる**
- 矢印キーと社名ボタンは `scrollTo({behavior:'smooth'})`

**実測（1280×631）。**停留所5つ、`scrollWidth` 6400 = 5 × 1280。
縮尺は ×0.94 → 1.02 → 1.13 → **1.25** → 1.13 で、作り替える前と同じ。
snap を外して途中の位置を入れると ×0.85 → 0.86 → 0.88 → 0.90 → 0.92 と連続で動く（＝混ざっている）。

**まだ確かめていないこと：実機のトラックパッドで、縦に回して横に進むか。**
合成した wheel イベントはブラウザのスクロールを起こさないので、
自動では確かめられない。**触って確かめること。**もし縦回しが効かない環境があったら、
`view.scrollLeft += e.deltaY` の1対1のハンドラを足す（閾値も時間も見ない形で）。
ただし上記のとおり mandatory snap とぶつかるので、そのときは snap を `proximity` に落とす。

**測り方の注意。**背面タブでは `requestAnimationFrame` が動かない。
自動で確かめるときは rAF を待たず、`draw()` を直に呼ぶこと。
`setTimeout` も背面では1秒に絞られるので、長い待ちを挟むと固まる（2回踏んだ）。

### 縮尺（G）

- **縮尺は枠の高さと幅の両方で決まる。**枠を大きく取るほど引いた絵になる。
  中身に対して枠が大きすぎると、その段だけ小さく見える
- 縦に伸ばすと縮尺が下がるが、**横に広げるぶんには下がらない。**
  字を大きくしたいときは横を使う（会社概要を 9.5px → 11.5px にしたのはこれ）
- **中央は枠ではなく実物で取る。**枠は寄り具合を決める数字で、中身の実寸とは一致しない。
  枠で取っていたら形の段が 39px 下にずれて、下の帯にかぶっていた
- 広い画面 5つ ×0.94 → 1.02 → 1.13 → **1.25** → 1.13／狭い画面は 6つ全部 ×1.00

### そのほか

- **幅 760px をまたぐと view の数が変わる**（会社の段が割れる／戻る）。
  `resize` で組み直して位置を丸めること。view は段と1対1ではないので、
  `sel`（複数可）で寄る先の箱を、`node` でどの段を濃く出すかを持たせてある
- **社名は `word-break:keep-all`。**入れないと語の途中で折れる（「株式会／社サーバーワークス」）
- **自動操作のタブではアニメーションが目視できない。**Chrome が
  `visibilityState=hidden` でタイムラインを凍結する（`timeline.currentTime=0`）。
  設定値は確認できるが、見え方は各自の画面で確認すること
- 高さの調整は**表示領域 1280×631** で詰めてある。スマホは 390×844 / 375×667 で実測
- **ワンライナーでのファイル編集はしないこと**（005 の運用メモ参照。2回壊している）
