## いまの形

```

           ↓ で 白紙 → 1 → 2 → 3 → 4 → 白紙 と回る（↑ は逆回り。数字キーも従来どおり）。

           AI が画面を見直し、決まっていない欄を3つ見つける。
```

## 判断の指針（今日決めたこと）

0. **決めたのが AI になっていないか、毎回みる。**AI は「決まっていない」と指摘するだけ。
   値は人が持ち寄る。だから埋まった値には部署が付き、紙は差戻しからもう一周する。
   ここを外すと、AI が勝手に決めた画面を人が黙って承認した話になる
1. **判断のない操作は置かない。**答えが一つしかない選択も置かない（偽の選択）
2. **決めるのは人、見つけるのは AI。**見つけたのが AI だと画面上で分かるようにする
3. **出すのは言葉ではなく物。**穴も、言葉のカードではなく物の上の空欄として見せる
4. **「これで通せる」と思わせてから外す。**漏れは段2では出さない
5. **咎める書き方をしない。**評価も価値の説明も置かず、事実と次の一手だけ
6. **段の名前と中身が食い違ったら、中身を直す。**名前を content に寄せるのは逃げ

## 書いてはいけないもの

- **根拠のない割合・数字。**「原因はたいてい決め忘れです」と書いて指摘された。
  要件不備が手戻りの大きな割合を占めるという研究はあるが、それを記憶から引いて
  断定すると、**会社がその数字を背負う**。実績値を持っていないなら、割合の話はしない。
  代わりに仕組みと結論だけ書く（決め忘れは作っている間は表に出ない → 先に出す）
- 同じ理由で、所要時間・削減率・件数の比較も、実案件の実測が出るまで書かない

## 見たうえで、直さないと決めたもの

「気づいていない」のではなく「見て、そのままにした」もの。蒸し返さないこと。

- **段2 の「決まったこと」を決めたのは誰か。**読者は一行しか書いていないのに、画面は
  「決まったこと」と見出しを付けている。段2で「決まった」と言い切って段3で
  「決まっていなかった」と言う、その線引きは規則表が引いていて、読者からは見えない。
  出どころラベル（「『…』から」）が上にあるので嘘ではない。**突っ込まれたら答えられる範囲**
- **完了通知に理念が載っている。**稟議の完了通知に理念は載らないので、書類としては様式が崩れる。
  下の会社概要とも重複する。それでもデモの締めとして会社を出す役目を優先する

## 未解決・次にやること候補

1. **見出しが未決。**いまは「決めていないことを、作る前に見つける。」。
   他の候補：作ってから気づくものを、決める前に出す／決めていないところが、いちばん高くつく
2. **書き上がりに約1.7秒（320 の待ち＋1250 の一筆＋130）。**2.3秒から詰めた。
   これ以上速くすると「書いている」ではなく「表示された」に寄るので、下限に近い。
   速度は `script.js` の `setTimeout(… 'sweep' …, 320)` と続く `320 + 1250 + 130`、
   CSS の `#rules.sweep`（`chalk 1.25s steps(24, end)`）。**変えるときは3箇所を揃えること**
   （`style.css` に `#rules.sweep` は2行ある。後ろの 1.25s が効いている）
3. **自由入力が語彙頼み。2026-08-28 に15件で実測、素直に通ったのは6件（4割）。**
   実演で自由入力を受けるなら、この打率で人前に出すことになる。**実運用するなら
   API 化が要る**（下記）。既知の外れ方は次の2つ。
   - **ひらがなを含む複合語が対象語にならない。**`subject()` の

## 運用メモ

- **CSS/JS は `?v=N` 付き。中身を変えたら番号を上げる。**
  GitHub Pages は Cache-Control を設定できないため、上げないと古い版が出る
- **死んだものは残さない。**付箋案・ゾーン振り分け案・「空欄のまま出す」案の残骸を一掃した
  （`style.css` 754 → 620 行、規則 49 件。`#blankRow` `#dropList` `#go` `leftBlank` も削除）。
  残っていると、次に触る人が「まだ使われているのか」を判断できない
- **`el.hidden = true` は `display` を書いた CSS に負ける。**この設計で3回踏んだ。
  `.seals{display:flex}` や `.app-body #holdBtns{display:flex}` があると、
  hidden にしても消えない。出す側の規則ぜんぶに `[hidden]` / `:not([hidden])` を足すこと
- ローカル確認は静的サーバが必要（`file://` では動かない。Chrome 拡張からも開けない）
- 高さの調整は**表示領域 631px** で詰めてある。実機ではもっと余裕がある
- **ワンライナーでのファイル編集はしないこと。**この設計中に2回壊した。
  - `perl -0pi -e` の中で `local(@ARGV,...)` を使い、`script.js` が 0 バイトになった。
    `node --check` は空ファイルを通すので気づけない
  - bash のダブルクォート内に `$('...')` を書き、シェルがコマンド置換して
    `sed` の正規表現が空になり、`.onclick` を含む行が全部消えた
- 004 のスケッチは消した。B（正解のない問い）C（現場↔経営）F（偽LPで落とす）は
  005 に採らなかったが、別方向として生きている。中身は `designs/IDEAS.md` に移した
