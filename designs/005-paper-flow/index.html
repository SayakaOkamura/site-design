      上流工程中心とは

      要件をすべて固めてから作り始めると、作っている間に前提が変わり、 できたものが要件と合わなくなります。だから順序を変えます。

      1. 一決める業務の単位、画面、テーブル、業務ルールを決める。
      2. 二すぐ動かす決めたことが、そのまま動く状態を作る。
      3. 三触って直す動くものを触って、決めたことの間違いに気づく。

      上で見たのは一と二です。三は実際の案件で、使う人と一緒に回します。 AI とローコードは、一から二までの距離を詰めるための道具として使っています。 道具が目的ではありません。

      このページについて

      会社案内を読ませる代わりに、事業内容をその場で通す作りにしました。 理念に「遊ぶように働く」と書いてあるなら、サイトも遊んでいるべきだからです。

      白紙に書いたことが付箋に分かれ、決めたものだけが稟議に載り、決裁されて完了しました。 決めなかったものは、載っていません。それがこの会社の扱っている問題です。
      実装は AI（Claude）が行いました。素の HTML / CSS / JavaScript のみ、ビルド工程なし。 なお付箋の切り出しはデモとして用意した結果で、その場で推論しているわけではありません。 実演したいのは推論ではなく、上流で決めたことがそのまま形になるという順序の方です。
